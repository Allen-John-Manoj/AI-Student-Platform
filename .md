### **Introduction**

Cursor is an AI powered code editor built to make development faster and more efficient. It combines the familiar look and feel of Visual Studio Code with extra tools that help you write, organize, and improve your code. Cursor can suggest better ways to structure your code, assist with repetitive tasks, and help you navigate complex projects more easily. It’s designed to reduce friction in your workflow so you can focus on building, not debugging. 

***

### **Features**

*   **AI Assistance**
    *   Provides intelligent, context-aware code completion and generation.
    *   Suggests fixes, optimizations, and boilerplate code based on project context.
    *   Supports natural language prompts for generating functions, tests, and documentation.

*   **Multi-language Support**
    *   Works with popular languages like Python, JavaScript, TypeScript, Java, and Go.
    *   Offers syntax highlighting, debugging, and AI-powered suggestions for each language.
    *   Compatible with language servers and frameworks for extended functionality.

*   **Git Integration**
    *   Built-in support for GitHub and Azure DevOps repositories.
    *   Enables clone, pull, push, commit, branch, and PR operations directly from the IDE.
    *   Provides AI-assisted PR summarization and release note generation.

*   **Real-time Collaboration**
    *   Allows multiple developers to work together using live editing sessions.
    *   Supports shared cursors, chat, and code review features similar to VS Code Live Share.
    *   Ideal for pair programming and distributed teams.

*   **Customizable Extensions**
    *   Fully compatible with VS Code extensions and marketplace.
    *   Supports plugins for CI/CD, testing frameworks, and cloud integrations.
    *   Enables developers to tailor the IDE to their workflow and project needs.
*   **Supports enterprise authentication (SSO, PAT)**
    *   Compatible with Single Sign-On (SSO) and Personal Access Tokens (PAT) for secure access.
    *   Meets enterprise compliance requirements for identity and access management.
    *   Facilitates smooth onboarding for teams with centralized authentication policies.

## **SCIM Provisioning**

SCIM (System for Cross-domain Identity Management) provisioning automates the process of creating, updating, and removing user accounts in Cursor based on your enterprise directory. This ensures seamless user management and reduces manual effort.


### Why Use SCIM?
- **Automatic User Management** – No need to manually add or remove users.
- **Real-Time Sync** – Changes in your identity provider reflect instantly in Cursor.
- **Centralized Control** – Manage users and groups entirely through your identity provider.

![Screenshot 2025-12-17 153704.png](/.attachments/Screenshot%202025-12-17%20153704-3691bc10-58a6-4f1f-8e52-af9bd6b3d666.png)

 Without SCIM, you need to manually add users to your Cursor team and remove them when they leave. With SCIM:

* New employees get Cursor access automatically when added to the right group
* Departing employees lose access when removed from your IDP
* Group membership changes propagate automatically


## Steps to Enable SCIM
#### **Prerequisites**
- Cursor **Enterprise plan**
- **SSO configured** (SCIM requires an active SSO connection)
- Admin access to your **identity provider**
- Admin access to your **Cursor organization**



## Setup Steps

### 1. Ensure SSO is Configured
- SCIM requires SSO to be set up first.  
- If you haven't configured SSO yet, follow the [SSO setup guide](#enterprise-controls) before proceeding.



### 2. Access Active Directory Management
- Navigate to:  
  ```
  https://cursor.com/dashboard?tab=active-directory
  ```  
  using an admin account, or  
- Go to your dashboard settings and select **Active Directory Management**.



### 3. Start SCIM Setup
- Once SSO is verified, you'll see a link for **step-by-step SCIM setup**.  
- Click this to begin the configuration wizard.



### 4. Configure SCIM in Your Identity Provider
In your identity provider:
- Create or configure your **SCIM application**
- Use the **SCIM endpoint and token** provided by Cursor
- Enable **user and group provisioning**
- Test the connection to confirm sync works



### 5. Configure Spend Limits
Back in Cursor's **Active Directory Management** page:
- View your synchronized directory groups
- Set **per-user spend limits** for specific groups as needed
- Review which limits apply to users in multiple groups  
(Group limits override team-wide limits)



## **Rules Configuration**

*   Rules provide system-level instructions to Agent. They bundle prompts, scripts, and more together, making it easy to manage and share workflows across your team.
*   There exists 4 types of rules:
    *   Project Rules
    *   User Rules
    *   Team Rules
    *   AGENTS.md
* Aside from Team Rules, everything else can be configured by an individual user within their own workspace. As such, I’ll be sharing my experience based on those features. Team Rules will have documentation as it's source

 ### **Project Rules**
*   Project rules live in `.cursor/rules`. Each rule is a folder containing a RULE.md file and is version-controlled. They are scoped using path patterns, invoked manually, or included based on relevance.

*   Use project rules to:

    - Encode domain-specific knowledge about your codebase
    - Automate project-specific workflows or templates
    - Standardize style or architecture decisions
* To access this, head to **File > Preferences > Cursor Settings**
![image.png](/.attachments/image-5eb5d0b7-2e11-4428-8746-68cbfda1f9bc.png)
* In **Cursor Settings**, head to **Rules and Commands** on the left panel, and scroll down till you see **Project Rules**. Click on **New Rule** to get two options, Custom Rule, and Import Rule (GitHub)
![image.png](/.attachments/image-b44bdf75-056f-4dd7-a5d1-a46b791caaa1.png)
* To use Imported Rules, select that option and enter the URL of your GitHub repo which contains the rules. This remote rule is synced to your repo, so any changes made here, will also change the GitHub rules for the same repo.
![image.png](/.attachments/image-479a38c0-aa06-42be-94db-9a4480723061.png)
* Clicking on **Custom Rule** prompts you to enter the name for this new rule
![image.png](/.attachments/image-552bd7c3-8c3d-4dc9-b318-c7a39d2af227.png)
* After entering the name and pressing Enter, you will be taken to a new file called `RULE.md`
![image.png](/.attachments/image-76fcb6d5-137d-4221-ad07-0738e9954dbb.png)
*   Each rule is a folder containing a `RULE.md` file with frontmatter metadata and content. Control how rules are applied from the type dropdown which changes properties `description`, `globs`, `alwaysApply`.
![Screenshot 2025-12-17 141839.jpg](/.attachments/Screenshot%202025-12-17%20141839-ff786e0b-c909-47b3-92c7-1926e9d2ecef.jpg)

*   Format of a `RULE.md` file
    ```
    ---
    description: "This rule provides standards for frontend components and API validation"

    alwaysApply: false
    ---
    - Use Cursor's internal RPC pattern when defining services
    - Always use snake_case for service names.
    @service-template.ts

    ...rest of the rule content
### **Team Rules**
*   Team and Enterprise plans can create and enforce rules across their entire organization from the Cursor dashboard. **Admins** can configure whether or not each rule is required for team members.

*   Team Rules work alongside other rule types and take precedence to ensure organizational standards are maintained across all projects. They provide a powerful way to ensure consistent coding standards, practices, and workflows across your entire team without requiring individual setup or configuration.
*   Team administrators can create and manage rules directly from the Cursor dashboard. Once team rules are created, they automatically apply to all team members and are visible in the dashboard

![Screenshot 2025-12-17 143207.jpg](/.attachments/Screenshot%202025-12-17%20143207-9b12f0b0-7754-49be-8f8b-54dc7e3fd07e.jpg)

* **Enable this rule immediately**: When checked, the rule is active as soon as you create it. When unchecked, the rule is saved as a draft and does not apply until you enable it later.
*   **Enforce this rule**: When enabled, the rule is required for all team members and cannot be disabled in their Cursor settings. When not enforced, team members can toggle the rule off in `Cursor Settings → Rules` under the Team Rules section.
*   Team Rules are free‑form text. They do not use the folder structure of Project Rules and do not support metadata such as globs, alwaysApply, or rule types. Rules are applied in this order: **Team Rules → Project Rules → User Rules**.

### **User Rules**
* User Rules are global preferences defined in **Cursor Settings > Rules and commands > User Rules > + Add Rule** that apply across all projects.
![image.png](/.attachments/image-897c196a-4ba2-43b2-bed8-7bc19a4043d5.png)
 
* They are used by Agent (Chat) and are perfect for setting preferred communication style or coding conventions. It is in plaintext format.

### **AGENTS.md**
* `AGENTS.md` is a simple markdown file for defining agent instructions. It is useful for projects that need simple, readable instructions without the overhead of structured rules. 
* Create a file named `AGENTS.md` and place it in your project root as an alternative to `.cursor/rules` for straightforward use cases. 
* You can create a new file by going to the ![image.png](/.attachments/image-0d94972d-aca7-410e-a4a4-51823b8a517d.png) icon on the left panel and naming it `AGENTS.md`
*   Unlike Project Rules, `AGENTS.md` is a plain markdown file without metadata or complex configurations. 
*   Example of an `AGENT.md` file:

    ```
    # Project Instructions

    ## Code Style

    - Use TypeScript for all new files
    - Prefer functional components in React
    - Use snake_case for database columns

    ## Architecture

    - Follow the repository pattern
    - Keep business logic in service layers

## **Azure DevOps in Cursor**

This describes how to connect **Cursor** to **Azure DevOps Git repositories** and validates that the standard source control workflows work correctly under enterprise authentication policies.

* Azure DevOps can be connected to Cursor via MCP (Model Context Protocol)
   > - Install and configure an Azure MCP Server
   > - In Cursor , go to 
   ` File -> Preferences -> Cursor Settings`
   > -  Under **Tools & Integrations**, choose **New MCP Server**, and edit your `mcp.json` to include:

![Screenshot 2025-12-17 222332.png](/.attachments/Screenshot%202025-12-17%20222332-8c8347b4-0b8c-4bd7-94ca-87aa7d58a97a.png)

> - Our MCP server has been added:


![Screenshot 2025-12-17 222305.png](/.attachments/Screenshot%202025-12-17%20222305-cbc817e2-e230-4405-89cf-1ee7a8e783a3.png)
- Install the Azure DevOps MCP server plugin

  ``` npm install -g cursor-azure-devops-mcp ```

 

- **Create `.env` File** In the same directory as the MCP server or where Cursor can access it:


```AZURE_DEVOPS_ORG_URL=https://dev.azure.com/your-org

AZURE_DEVOPS_TOKEN=your-personal-access-token

AZURE_DEVOPS_PROJECT=YourProject

PORT=3000

LOG_LEVEL=info
```

### **Recommended Setup**

- SSH authentication → best reliability and least friction
- Enterprise SSO (Microsoft Entra ID) → works automatically via Git Credential Manager
- PAT (HTTPS) → supported but less ideal due to token expiry/rotation

### **HTTPS + PAT Authentication**

#### 1. Create a Personal Access Token (PAT)
- Azure DevOps → **User settings → Personal access tokens**
- Create new token
- Scope: **Code (Read & Write)**
- Copy the token (shown only once)

![Screenshot 2025-12-17 235801.png](/.attachments/Screenshot%202025-12-17%20235801-1c5fae2e-ec03-4530-b778-e3e921be7ca0.png)

#### 2. Copy Repository HTTPS URL
From **Repo → Clone → HTTPS**:

```
https://dev.azure.com/<ORG>/<PROJECT>/_git/<REPO>
```


#### 3. Clone Repository in Cursor
- Open Cursor
- Press `Ctrl + Shift + P`
- Select **Git: Clone**
- Paste the HTTPS URL
- Choose local folder


#### 4. Authenticate When Prompted
- **Username:** email or any placeholder value
- **Password:** Personal Access Token


## **Remarks**

Connecting Cursor to Azure DevOps repos works, but it’s not as smooth as GitHub. GitHub integration feels almost effortless, while Azure DevOps requires extra steps and configuration, which can be a bit of a hassle for teams. Once set up, it runs fine, but the initial experience could be more streamlined. Overall, repo connectivity for GitHub is **5/5**, while Azure DevOps integration is closer to **3.5/5** due to setup complexity.

## **Security and Compliance**

* Cursor is SOC 2 Type II certified.  SOC 2 is a framework developed by the American Institute of Certified Public Accountants (AICPA) and evaluates security, privacy, confidentiality, etc. Type II means the operating effectiveness of those controls were evaluated over 6–12 months.
![image.png](/.attachments/image-76d7c714-133d-4083-89cd-c86941346e6f.png)
* Cursor is **one of three** independent AI companies that have this certification in 2025, the other two being Anthropic (Claude) and OpenAI.
* You need to be an **enterprise** admin to request access to this audit, so I can't access it. 
* Cursor also performs at-least-annual penetration testing by reputable third parties. Again, I don't have access to the audit.
![image.png](/.attachments/image-4660d441-efe3-480c-a8c2-525dd4d780c1.png)
* Cursor's documentation highlights how information is stored by the agent and it's subprocesses.
   * When you open a project in Cursor, Cursor create embeddings that represent your code. These embeddings power semantic search across your codebase.

     **What gets sent:**
     *   Your code, temporarily, to create embeddings
      *   Nothing is stored; embeddings are generated and the original code is discarded

     **What gets stored:**
     *   One-way mathematical embeddings (vectors) that represent code semantics
     *   Obfuscated file paths
     *   Line numbers
  * When you use AI features, we send prompts and code context to language model providers like OpenAI, Anthropic, and Google.

      **With Privacy Mode enabled:**
     *   Code is never stored by model providers
     *   Code is never used for training
     *   We maintain Zero Data Retention (ZDR) agreements with all providers
    * **It should be noted Privacy Mode is OFF by default**. For enterprise accounts, Privacy Mode is ON
   * Cloud Agents are the only feature that requires Cursor to store code. Unlike the indexing process or LLM requests, Cloud Agents need access to your repository over time to make changes. Cloud Agents are **optional** and can be turned off

     **Architecture:**
     *   Agents run in isolated virtual machines
     *   Each agent has a dedicated environment
     *   Isolated from other agents and users

     **What gets stored:**
     *   Encrypted copies of repositories that Cloud Agents work on
     *   Stored temporarily while the agent runs
     *   Deleted after the agent completes 
* On July 2025, a high-severity vulnerability was discovered. It allowed Remote Code Execution (RCE) via malicious prompt injections in the MCP configuration.
![image.png](/.attachments/image-9c498094-c97d-4650-83fb-2ad992a30339.png)
* From forums, a possible security violation was found. Even with Privacy Mode enabled, if you use Vibe Code and allow the agent to run `env` or `printenv`, secrets may appear in the chat history, which is retained for 30 days for safety monitoring. 
* In response to this, Cursor introduced a new file called `.cursorignore`. Similar to `.gitignore`, it can be used to prevent Cursor from reading sensitive files like `.env`, `id_rsa`, or `credentials.json`. This file can be created by simply creating a **New File** with the name and typing in the names of the file you want Cursor to ignore (eg: `MCP.py`)
* For enterprises, Cursor Enterprise includes SSO integration via SAML/OIDC. You can integrate Okta, Microsoft Entra ID, Google Workspace, etc., for centralized authentication. It also supports SCIM 2.0 provisioning for automatic synchronization of user accounts and groups from your identity provider. 
* For enhanced security control, enterprise customers can use Customer Managed Encryption Keys (CMEK) for encrypting data stored in Cursor's infrastructure.
With CMEK enabled:
  *   Embeddings are encrypted using your customer encryption key
  *   Cloud Agent data is encrypted using your customer encryption key
  *   You control key rotation and access
  *   Provides additional layer of security beyond standard encryption

* [Superblocks](https://www.superblocks.com/blog/cursor-enterprise) has  highlighted the following problems with Enterprise accounts in Cursor:
  *   **Overzealous code changes that introduce hidden bugs:** Cursor’s agent mode can generate large, multi-file code edits, which are hard to review line by line. [Users](https://www.reddit.com/r/CursorAI/comments/1k3uz9k/my_honest_review_after_3_months_with_cursorai/#:~:text=I%C2%A0review%20every%20single%20line%20of,using%20branches%2C%20small%20commits%2C%20everything) complained that it might suddenly change code or delete it entirely. You have to check what it broke, which is hard if the commits don’t reflect the edits.
    *   **Stability and scale issues on large codebases:** [Some users](https://www.linkedin.com/posts/devansh-devansh-516004168_ive-spent-hundreds-of-hours-evaluating-cursor-activity-7318693323135684608-NI7Z#:~:text=does%20not,https%3A%2F%2Flnkd.in%2FdQh6f_Tz%20PS%3A%20If%20you%E2%80%99re) found that Cursor struggles with very large or complex repos. It can crash or slow down when indexing huge monorepos or when agent mode attempts a complex task across the codebase.
  *   **Limited oversight:** Cursor Enterprise doesn’t support a detailed audit log of AI activities. Nothing stops a dev from using Cursor with a personal account on corporate code, aside from policy.
  *   **No Linux policy management**: Enterprise configuration profiles are supported on Windows and macOS, but Linux support isn’t on the roadmap.


### **Remarks**
 

Cursor appears to be highly compliant with security standards with SOC 2 Type II certification and annual penetration testing, which is reassuring. However, despite these measures, vulnerabilities have been discovered, and the platform remains susceptible to common pitfalls associated with agentic AI systems. While compliance earns a solid **5/5**, actual security performance doesn’t quite match its peers, so I’d rate it **3/5**.
